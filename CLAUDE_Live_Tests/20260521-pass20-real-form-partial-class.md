## Composition path decision

Designer.cs is hand-shaped (not auto-generated by VS — no `// <auto-generated>` header, custom hand-laid `MainViewer = new SchemaViewer()`). Per README guidance "consider whether runtime setup in the main partial is safer than editing designer layout code," I judged it safe to edit — and the test EXPLICITLY wants sibling partials in one session for overlay coupling, which an all-main-partial design wouldn't exercise.

Final plan:
- **`SchemaStudio.cs`** (main partial): add `_greetingLabel` field, `GreetingButton` field, `OnGreetingButtonClick` handler method.
- **`SchemaStudio.Designer.cs`** (designer partial): replace `InitializeComponent()` body to instantiate `GreetingButton`, set properties, wire `Click += OnGreetingButtonClick`, add to `Controls`.

Cross-partial references probed by overlay: `GreetingButton.Click += OnGreetingButtonClick` (handler defined in main partial), `Controls.Add(GreetingButton)` and `GreetingButton = new Button()` (field defined in main partial). **Designer cannot compile in isolation; the coupling is real.**
