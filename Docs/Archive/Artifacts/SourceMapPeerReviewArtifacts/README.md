# Source Map Peer Review Artifacts

These artifacts were generated by MonitorBaseClaude against the real watched DBV2 project:

```text
Watched project: C:\Schema Studio - DBV2
Surface folder: EditorSurface
Focused file: EditorSurface\EditorSurfaceControl.cs
```

## Purpose

Review whether `get_source_map` gives Claude/Codex enough structure to choose narrow follow-up reads before editing.

This artifact set was regenerated after source-map hardening:

- type symbols now include syntax-level `baseTypes`
- event declarations and event fields are surfaced as `event` symbols
- signatures strip leading trivia so comments, emoji, and glyphs do not become accidental source-map anchors
- file entries include `parseStatus`, `diagnosticCount`, and `diagnosticsSummary`
- symbols include structured `returnType`, `parameterTypes`, `parameterNames`, `arity`, symbol flags, `syntaxKind`, and structured `attributes`

The intended agent loop is:

```text
find_file
get_source_map for target file/folder
get_symbol for the exact method/member body needed
stage a full candidate
WinMerge sanity review
record_diff_decision vote-plus-hash classification
```

- `EditorSurfaceControl.file.source-map-raw.json`: raw MCP `get_source_map` response for the focused control file.

## Review Questions

1. Is the folder source map enough to identify related files and likely next reads without loading full file bodies?
2. Is the focused file source map enough to choose `get_symbol` targets such as `LoadTable` or `InitializeComponent`?
3. Are signatures, line spans, stable symbol keys, hashes, structured attributes, structured method fields, containing types, and `baseTypes` sufficient for safe symbol selection?
4. What fields are missing before using this as the default pre-edit context for Claude Desktop or Claude Code?
5. Does the artifact expose too much, too little, or the right amount for token-efficient agent work?

## Known Limitations

- Source maps are read-only discovery artifacts, not accept/reject gates.
- The final gate is still vote-plus-hash classification through `record_diff_decision`.
- Razor files are not covered by this C# Roslyn source map path.
- The current source map does not include method bodies; use `get_symbol` for bodies.
- `baseTypes` are syntax-level text, not full semantic interface resolution. Use Roslyn CodeLens for deeper hierarchy/implementation questions.
